### Third batch: M2 and frontend

**M2 (backend).** `verificationFailed(serviceId, status, key)` now handles a failed verification run as follows:
- If the run is unhealthy and was recorded **after the latest verify request**, it writes a `verification-failed` system event.
- It then re-queues the investigation as a new attempt: fresh evidence, a new Workflow ID, and the outbox set back to pending. The callers already reconcile afterwards, so the attempt is dispatched.
- If all 5 attempts are used, the incident goes to `awaiting_operator` instead.
- Replaying an older probe run, or the same run twice, changes nothing. This also covers the old demo-replay path at `src/index.ts`.

Tests: the rewritten "does not infer causes from recovery alone…" covers the replay no-op, the re-queue to attempt 2, cleared evidence, the pending outbox, the event and idempotency. A new test, "returns a failed verification to the operator once the attempt cap is used", covers the cap.
